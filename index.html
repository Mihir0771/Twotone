How a message travels

  1. Text to bytesYour message is encoded as UTF-8 bytes, the same as any text file.
  2. Bytes to bitsEach byte becomes 8 bits — a string of 0s and 1s.
  3. FramingA sync pattern, a length byte, and a checksum are added around your message so the receiver can find the start of a transmission and verify it arrived correctly.
  4. Bits to tonesEach bit is played as a short burst of one of two tones: 18.5 kHz for 0, 19.5 kHz for 1. Both sit just above where most adult hearing fades out, so the transmission is largely inaudible.
  5. ListeningThe receiving device's microphone picks up the sound, and a filter tuned to exactly those two frequencies measures which one is louder at each moment.
  6. Tones back to textThe decoded bits are reassembled into bytes, the checksum is checked, and your message is displayed.

The frame

This is the exact structure sent for every message:

Preamble24 alternating bits
Sync wordmarks frame start
Length1 byte
Messageyour text, in bytes
ChecksumCRC-8

In robust mode every bit above is sent three times in a row, and the receiver takes a majority vote per bit — a form of forward error correction that trades speed for reliability.

Getting a reliable link

  • Use each device's built-in speaker and microphone — Bluetooth audio almost never passes frequencies this high.
  • Keep the devices within a metre or so of each other, speaker facing microphone.
  • Turn the sending device's volume all the way up.
  • Test in a quiet room — fans, traffic, and music can share this band.
  • If messages keep failing the checksum, turn on robust mode, or increase the bit duration in Calibrate.
  • Older phones and laptop microphones sometimes roll off above 18 kHz in hardware — the self-test in Calibrate will show you whether yours can hear it at all.
